# План реализации: Безопасность Production, Защита Админа и Настройки Профиля

## 1. Обзор задачи
Необходимо подготовить платформу к безопасному промышленному использованию (production-ready):
1. **Смена пароля в настройках пользователя**: добавить форму в модальное окно профиля/настроек с проверкой текущего пароля и валидацией нового пароля.
2. **Очистка интерфейса от отладочных подсказок**: убрать все тестовые бейджи, подсказки с паролями/логинами, скрытые технические плашки, не предназначенные для рядовых пользователей.
3. **Схема блокировки регистрации пользователей**: добавить глобальный переключатель в админ-панель ("Разрешить/запретить открытую регистрацию"), сохранять статус в SQLite `site_settings` и блокировать эндпоинт `/api/auth/register`.
4. **Защита прав главного администратора**: заблокировать возможность изменения роли, блокировки, кика или удаления супер-администратора (`admin`). Реализовать удобное управление ролями и блокировками других пользователей в админке.
5. **Комплексные стандарты безопасности**:
   - HTTP-only Secure Cookies для хранения сессии авторизации (`auth_token`) с поддержкой Bearer токенов.
   - Защита CORS с контролем доверенных источников.
   - Защитные HTTP-заголовки (Helmet / Content-Security-Policy, X-Content-Type-Options, Frameguard).
   - Защита от перебора паролей и brute-force атак (Rate Limiting на маршруты `/api/auth/*`).
   - Валидация входных данных и экранирование.

## 2. Архитектурные изменения

### Бэкенд (`server.ts`, `src/server/db.ts`)
1. **Зависимости безопасности**:
   - `cookie-parser` (парсинг безопасных сессионных куки).
   - Подключение middleware защиты: установка заголовков безопасности (Helmet-like security headers), ограничение частоты запросов (Rate Limiter в памяти/Redis-like на попытки авторизации).
2. **Сессии и Куки**:
   - При `/api/auth/login` и `/api/auth/register`: выставлять HTTP-only cookie `vibopedia_session` (`SameSite=Lax`, `Path=/`, `HttpOnly=true`, `Max-Age=30 days`, `Secure` при HTTPS).
   - При `/api/auth/logout`: удалять cookie.
   - Вспомогательная функция `getAuthenticatedUser(req)`: извлекает токен сначала из cookie `vibopedia_session`, затем из заголовка `Authorization: Bearer <token>`, сохраняя полную совместимость.
3. **Маршрут смены пароля** (`POST /api/auth/change-password`):
   - Требует авторизацию.
   - Принимает `currentPassword`, `newPassword`, `confirmPassword`.
   - Проверяет корректность `currentPassword` через `dbService.verifyUserPassword`.
   - Проверяет минимальную длину (не менее 8 символов).
   - Хеширует новый пароль с уникальной солью и сохраняет в SQLite базу данных.
4. **Блокировка свободной регистрации**:
   - Добавить поле `allowRegistration: boolean` в таблицу `site_settings` (по умолчанию `true`).
   - Эндпоинты: получение и сохранение настройки в админском API (`/api/admin/settings`).
   - Middleware в `POST /api/auth/register`: если `allowRegistration === false`, отклонять регистрацию со статусом 403 ("Регистрация новых пользователей временно закрыта администратором").
5. **Защита аккаунта главного администратора**:
   - На уровне сервера запретить:
     - Изменение роли супер-администратора `usr-admin` / username `admin`.
     - Блокировку (`isBanned: true`).
     - Удаление аккаунта супер-администратора.
   - На уровне админ-панели блокировать кнопки действий для аккаунта главного администратора.
6. **Очистка данных и окружения**:
   - Убрать любые всплывающие/демонстрационные плашки с готовыми паролями ("admin / admin123" и подобные тестовые подсказки).

### Фронтенд (`src/components/*`, `src/App.tsx`)
1. **Модальное окно профиля (`UserProfileModal.tsx`)**:
   - Вкладка/раздел "Безопасность и пароль".
   - Поля: "Текущий пароль", "Новый пароль", "Повторите новый пароль".
   - Индикатор надежности пароля и сообщения об ошибках/успехе.
2. **Панель управления администратора (`AdminPanel.tsx`)**:
   - Раздел "Управление доступом и регистрацией": переключатель "Разрешить свободную регистрацию на платформе".
   - Таблица пользователей: управление ролями (user, editor, moderator, admin) и блокировками (Бан / Разбан), визуальный бейдж "Суперадминистратор" без возможности случайного снятия прав или удаления.
3. **Форма входа и регистрации (`AuthModal.tsx`)**:
   - Очистить интерфейс от тестовых подсказок и плашек для разработчиков.
   - Если регистрация отключена — информационное сообщение о закрытом доступе вместо формы регистрации.
4. **Удаление лишних UI-элементов**:
   - Проверка всех компонентов на наличие нежелательных отладочных надписей и подсказок.

## 4. Критерии готовности
- [ ] Пользователь может безопасно изменить свой пароль из настроек профиля только после подтверждения текущего пароля.
- [ ] Сессия авторизации надежно защищена HTTP-only cookie с флагами SameSite=Lax.
- [ ] Администратор может одним кликом в панели закрыть или открыть регистрацию новых пользователей.
- [ ] Попытка заблокировать или понизить права супер-администратора отклоняется сервером и заблокирована в интерфейсе.
- [ ] Никакие тестовые учетные данные и подсказки не отображаются рядовым посетителям.
- [ ] Успешное прохождение компиляции и интеграционных тестов сборки Docker/Coolify.
